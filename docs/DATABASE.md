# Database

## Phase 0 schema

PostgreSQL is the application database. The API uses SQLAlchemy 2 and
`psycopg` 3; Alembic tracks schema revisions. Phase 0 creates **no
career-domain tables**. Revision `0001_phase_0_baseline` intentionally records
the starting point so later schema changes have a stable predecessor.

The shared SQLAlchemy base provides:

- Native PostgreSQL UUID columns, with UUIDs generated by the application.
- Timezone-aware `created_at` and `updated_at` timestamps.
- A metadata naming convention for indexes, unique constraints, checks,
  foreign keys, and primary keys.

PostgreSQL and application processes use UTC. Connections use SQLAlchemy's
`pool_pre_ping` to detect stale pooled connections. The API readiness check
executes `SELECT 1` and returns HTTP 503 when the database cannot be reached.

## Configuration

Set `DATABASE_URL` with the `postgresql+psycopg` driver. The checked-in
`.env.example` is only suitable for a local development environment. Never
commit live credentials or use the example password on a shared deployment.

## Migrations

Run from `backend/` after installing the project:

```powershell
alembic upgrade head
alembic current
```

When domain models are introduced, import them into Alembic's metadata
bootstrap, generate a reviewed revision with `alembic revision --autogenerate
-m "description"`, and verify both upgrade and downgrade behavior against a
disposable PostgreSQL database. Do not edit an already-applied revision.

For deterministic unit tests, backend connectivity tests use an in-memory
SQLite engine. The Compose API health check exercises PostgreSQL itself.
